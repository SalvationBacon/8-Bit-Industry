## Overview

**Genre:** Factory automation. **Not an idle game** (the user decided in v2.0.28): the factory runs only while the game is open, and there is no offline progress
**Platform:** PWA (single HTML file) for phones first, with tablet and desktop layouts and keyboard controls (v2.0.34), and an Android app for Google Play (v2.0.38, Capacitor, see *Play Store app*)
**Aesthetic:** Dark pixel art, Press Start 2P font, amber/teal accent palette
**Tagline:** Start with nothing · Automate everything · Launch
**Current build:** v2.0.46, all five zones: Ironfield → The Scar → The Deep → The Bloom → The Singularity, plus the Big Bang and Stardust prestige
**Working file:** `index.html`, ~7,000 lines, single file, never split
**Live URL:** https://salvationbacon.github.io/8-Bit-Industry/

## Dev Mode

**Unlock:** ☰ menu → 🔒 DEV tile → type `BIGBANG` · **Disable:** type `BIGBANGOFF` · **Not in the Play Store app** (only inside a sandbox there)
Persists as `G.devMode`. The DEV tile then opens the dev panel, and a purple **⏩ speed button** appears in the top bar.

- Sim speed `DEV_SPEEDS` ×1 / ×2 / ×5 / ×10 / ×25 / ×50: tap ⏩ to cycle, or pick in the dev panel. `startTick()` runs several ticks per timer interval above ~16×. UI refresh (220ms) and autosave (8s) are throttled by real time so high speeds stay smooth
- Free crafting / free building toggles; unlock all techs
- Give resources (per item) + Give All ×500
- `devCompleteRocket()`: Zone 1 rocket parts + Rocket Science
- `devCompleteZone()`: researches every tech of the current zone (plus Zone 1's) and gives everything the zone's launch needs (Zone 5: the Singularity components)
- Reset save (confirmed, reloads page). Never touches `ebi_prestige`.

## Save System

| Key | Contents |
|---|---|
| `ebi_save` (`SAVE_KEY`) | Autosave, the full `G` |
| `ebi_save_slot1..3` | Manual slots |
| `ebi_prestige` (`PRESTIGE_KEY`) | Stardust, Big Bang count, owned Stardust upgrades, theme. **Never wiped** by resets or new games |
| `ebi_blueprints` (`BP_KEY`) | The blueprint library (v2.0.26): one list for the device, shared by every save, slot, zone and Big Bang; in backup codes. **Never wiped** by resets or new games |
| `ebi_sandbox` (`SANDBOX_KEY`) | The sandbox game (v2.0.27), a full `G` with `sandbox:true`. `saveKey()` picks it whenever `G.sandbox`, so a sandbox never writes over `ebi_save`; manual slots refuse in a sandbox |
| `ebi_times` (`TIMES_KEY`) | Run timer bests (v2.0.29): `{z:{zone:ticks}, run:ticks}`. **Never wiped**; in backup codes (an older backup without it leaves the device's alone) |
| `ebi_prefs` (`PREFS_KEY`) | Device prefs: `{fps:30\|60, res:1..0.1, haptics, music, sfx, musicVol, cb, timer, keyHints, audioSet, supporter, gild}` (`supporter`: the Supporter Pack is owned, `gild`: Gilded Machines on) (`cb`: colour-blind mode, `timer`: show the run timer). **Every setting is device-wide (v2.0.33)**: sound (`sfx`, `music`, `musicVol`) moved here from the save (`G.sfx`/`G.music`/`G.musicVol`, gone from `defaultState`). `migrateSave()` hands the first loaded save's sound over once (unless `audioSet`, set by any sound change or a new game) and deletes the keys from the save. Not part of any save or backup |

- Autosave every 120 ticks (30s) and on place/remove, research, launch, perk purchase, **and when the app is hidden or closed** (`visibilitychange`, `pagehide`).
- `noSave` blocks every save. Set it before any `location.reload()` that follows a storage change (dev reset, backup import), or the save-on-hide writes the old game back.
- **Backups** (`BACKUPS` section): `makeBackupCode()` packs the autosave, the 3 slots, `ebi_prestige`, `ebi_times` and `ebi_blueprints` (an older backup without blueprints leaves the device's library alone) into `EBI1.` + base64(gzip JSON) (`EBI0.` without gzip where `CompressionStream` is missing). `readBackupCode()` validates. ☰ → 🛟 BACKUP and the title screen offer export (copy or .txt file) and import (paste or file, confirmed, then reload). `navigator.storage.persist()` is requested on load.
- Saves go through `serializeG()`. It packs the map to one character per tile (`packMap`, `#` for a cave wall; a full Zone 5 map went from ~950 KB to ~36 KB), and `migrateSave()` unpacks it (`unpackMap` rebuilds machine tiles from `G.machines`). Old unpacked saves still load. It also drops transient per-tick keys (`TRANSIENT_KEYS`: `_net`, `_nets`, `_fluidStatus`). Fluid networks are circular and would break `JSON.stringify`.
- **A save that won't load is never replaced (v2.0.39):** `continueGame()` used to call `newGame()` on any load error, and the autosave then wrote over the save. Now `saveWontLoad(key,raw,err)` leaves it untouched, keeps a copy in `ebi_broken_save` (`BROKEN_KEY`), returns to the title and offers BACKUP with the error text. store-test `broken_save_kept`.
- Load paths `continueGame()` and `loadFromSlot(s)` both backfill keys and call `migrateSave()` (renames, e.g. `tutorialZ2` → `zoneTut`). New top-level keys need a default in **both**, or in `migrateSave()`.

**State keys in `G`** (declared in `defaultState()`):

```js
ver, tick, _savedAt     // (sfx, music, musicVol lived here until v2.0.33: now PREFS)
zone         // 1–5
smog         // 0–100 (zones with the 'smog' hazard)

map          // MAP_H × MAP_W tiles {type,res,mid,items}; size is per zone (see ZONES.mapSize)
machines, nextId

cam, craftState

achievements // [id] — carried across zones (since v1.2.0)

zoneTut      // step in ZONE_TUTORIALS[zone] (-1 = done, undefined = none)

```

## Zones — `ZONES` table

Every zone-specific behaviour reads `ZONES[n]` (defined after the rocket-part arrays). To add or change a zone, edit its entry:

| Field | Meaning |
|---|---|
| `name`, `icon` | Display |
| `rocketTech` | Tech that unlocks the launch (`null` in Zone 5) |
| `parts`, `fuel` | Launch requirements (`rocketReqs()` merges them) |
| `partsCat`, `partsLabel` | Item category for that zone's rocket parts (inventory shows only the current zone's) |
| `sci` | Science packs shown in the research panel |
| `hazards` | Any of `smog`, `pressure`, `glow`, `decay`, `heat`. Checked with `zoneHas()` and drive the HUD gauges and simulation |
| `buildMap`, `mapSize` | Map generator and size |
| `launchLabel`, `launchText`, `launchTease` | Launch modal |
| `arrivalTitle`, `arrivalHtml`, `arrivalBtn` | Arrival / new-game modal |
| `renderPanel`, `menuRocketHtml`, `onDevComplete` | Optional overrides (Zone 5 uses them for the Singularity) |

Helpers: `zoneDef()`, `zoneHas(h)`, `nextZone()`, `rocketUnlocked()`, `rocketReqs()`, `zoneTechs(z)`, `syncMapSize()`, `updateZoneTabs()`.

**Transitions:** `launchRocket()` (any zone) → `continueToNextZone()` → `transitionToZone(n)`. That replaces `G` with `defaultState()` and keeps **research, perks, achievements and devMode** (sound is a device setting, `PREFS`). It then applies Quick Start and Remembered Tools, builds the map, starts the zone tutorial and shows the arrival modal. After a launch, the Rocket panel, the ☰ Rocket section and the Perks panel offer **CONTINUE TO ZONE n →** instead of relaunching.

| Zone | Name | Hazards | Map | Goal |
|---|---|---|---|---|
| 1 | Ironfield | — | `buildMap()` 96×64 (+32 floor rows) | 4-part rocket |
| 2 | The Scar | smog | `buildMapZ2()` 96×64 | 6 repair parts + 20 refined fuel |
| 3 | The Deep | pressure, glow | `carveCaves(buildZoneMap(DEPOSITS_Z3))` 96×64, cave walls | 5-part escape-shaft rocket |
| 4 | The Bloom | pressure, decay, heat | `buildZoneMap(DEPOSITS_Z4)` 96×64 | 4-part hyperfuel rocket |
| 5 | The Singularity | all five | `buildZoneMap(DEPOSITS_Z5)` 128×80, expandable to 192×112 then 256×144 (`EXPAND_W` 64, `EXPAND_H` 32 per Expansion since v2.0.25) | Build + power the Singularity → Big Bang |

**Factory Floor (v2.0.0, halved in v2.0.4):** every map gets `FLOOR_ROWS` (32) rows of open ground below its ore fields (`addFactoryFloor()`, used by `defaultState()` and `transitionToZone()`). `G.floorY` is the first floor row, so a map is `mapSize[1] + 32` tall (Zone 1: 96×96). The floor draws with the zone's normal ground (`groundSpr`), the same as the rest of the map (the plated `floorSpr` with a hazard stripe was dropped at the user's request). Old saves get a floor in `migrateSave()` and a one-time toast; `trimFactoryFloor()` drops empty rows from the old 64-row floor (never a row with a machine, item or deposit; Zone 5 keeps `EXPAND_H` (32) extra rows per Expansion). Zone 5 `expandMap()` only puts new deposits in new columns of the ore band, never on the floor. Arrival messages no longer mention the floor (the `FLOOR_NOTE` line was removed in v2.0.24 at the user's request).

`buildZoneMap(deposits, salt, w, h, accept)` places `[res, wMin, wMax, hMin, hMax]` patches with a 1-tile gap. `accept` filters positions; `expandMap()` uses it to put new deposits only in new territory.

## Pixel-art textures

All textures are procedural (`PIXEL SPRITES` section): `mkSpr(key,w,h,fn)` draws into a tiny offscreen canvas once and caches it. The pixel API is `P` pixel, `R` rect, `C` filled circle, `O` ring and `L` line. Draws are scaled with `imageSmoothingEnabled=false`.
- `groundSpr(zone,v)` per-zone floor (`GROUND` palettes; Zone 5 uses `voidGroundSpr(v)` since v2.0.24: near-black space, nebula haze, stars and a glowing violet lattice on the tile seams, so it no longer reads as a darker Bloom); `resSpr(res,v,frame)` deposits (`ORE_ART`, pools animate); `wallSpr(mask,v)` Zone 3 cave rock (v2.0.28: `wallMask(x,y)` bits 1 up, 2 right, 4 down, 8 left say which sides face open ground; a lit rim, a cliff face above open floor, glowing crystals, 8 variants; the floor tile under rock gets a shadow; baked into the ground chunks)
- `machineSpr(type,frame,on)`: `MACHINE_ART[type](api,frame,on)` at 16px per tile (Singularity 80px). There are 4 frames while `machineWorking(m)`. `chassis()`, `gearArt()` and `fire()` are shared helpers
- `beltSpr(frame)` tread, rotated by direction; `stageSpr()` life-stage badges
- `itemSpr(id,frame)`: `ITEM_ART[id]=[shape,c1,c2,c3,extra]` + `ITEM_SHAPES` (69 shapes). **Every item has its own silhouette**; science books share a shape but each has its own cover emblem (`BOOK_EMBLEMS`, `extra` = index). `ITEM_GLOW` items get a 4-frame glint on the canvas
- **Every machine animates while working**, including tanks, accumulators, heat sinks, chests and valves (`machineWorking()` defines when). On the map, splitters (`machineSpr('splitter')` rotated), tunnels (`machineSpr('tunnel')` + `arrowSpr`), pipes (`pipeShellSpr(mask,hot)` + `pipeCoreSpr(mask,col)` at pressure opacity), tier badges (`tierSpr`), port arrows and the placement arrow (`arrowSpr`) and module badges (`drawItem`) are pixel sprites. Round effects (Singularity rings, pipe bursts) go through `pixelFx()`: drawn at 16px per tile, then scaled up unsmoothed. Map labels use Press Start 2P
- **Every icon goes through `iconHtml(id,fallback)` (DOM) or `drawItem()` (canvas).** A new item needs an `ITEM_ART` entry; a new machine needs a `MACHINE_ART` function
- Pixel art is the only style (the user removed the emoji toggle). **UI icons** are pixel art too: `UI_ART[name]` (16×16) + `uiIcon(name)`, used by the tab bar and title (`data-ui="name"` spans filled on load), EDIT tools, ☰ menu tiles, HUD gauges, panel headers, and modal titles (`TITLE_UI` maps a leading emoji in a `showModal` title to its icon). **Tutorial text that names a build group (`BUILD → Power → [[burner]]`) is checked by play-test `tutorial_menu_names`. Tutorial text and toasts** go through `pixEmoji()`: `EMOJI_PIX` maps each emoji to `ui:name` or an item/machine id (`toast()` escapes the text first). **Achievements** use `achIcon(a)` (`ACH_PIX` per id; a new achievement needs an entry). **Nothing on screen is emoji or a text symbol (v1.9.0).** `pixEmoji()` is HTML-aware (text only, never attributes) and runs inside `setHtml()`, `showModal()` and `toast()`; a `MutationObserver` (`watchEmoji()`/`pixifyNode()`) converts anything else that reaches the DOM as text. `emojiTable()` merges `EMOJI_PIX` with every `ITEMS`/`MDEFS` icon (→ its sprite); arrows, ✓ ✕ ☰ ↻ map to UI icons. Converted icons get `.pxe` and scale with the surrounding font. A brand-new emoji still needs an `EMOJI_PIX` entry (or an item/machine with that icon)

## Play Store app (v2.0.38, `PLAY STORE APP` section above BOOTSTRAP)
- **One game, two builds.** `const STORE_BUILD=false` (after `VER`); `tools/build-app.js` writes `www/index.html` with it true, and Capacitor wraps `www/`. Everything store-only checks `STORE_BUILD`, so the web game is unchanged (store-test `web_build_unchanged`).
- **Store build:** no DEV tile or BIGBANG unlock unless `G.sandbox` (`openBigMenu`, `promptDevUnlock`), and `startGame()` turns dev mode, free build/craft and dev speed off for a non-sandbox save; `canInstall()` is false; no service worker; `initNative()` adds `body.store` and listens to the Capacitor App plugin: `backButton` → `androidBack()` (`escapeStep()`, which is now what Esc runs, then the ☰ menu in a game, then `minimizeApp` on the title), `pause` → `appHidden()` (music off, save, stop `tickId`, `simPaused`), `resume` → `appShown()`. `capacitor.config.json` also sets Cordova `KeepRunning` false so WebView timers pause. The factory never runs in the background (not an idle game).
- **Supporter Pack:** a one-time Google Play product `SUPPORT_ID` `supporter_pack`. `initBilling()` (on `deviceready`) registers it with `window.CdvPurchase.store`, `.approved(t=>t.finish())` acknowledges, `refreshSupporter()` reads the price and `store.owned()` and calls `grantSupporter(fresh)`. `PREFS.supporter` keeps ownership on the device; Google confirms it every launch (store-test `supporter_restored_on_launch`). `openSupport()` (title button `#titleSupport`, ☰ SUPPORT tile, UI icon `support`, emoji 💛) shows BUY · price, RESTORE PURCHASE, errors, or, once owned, the switches `setSupporterTheme()` and `setGild()`; `refreshSupportModal()` redraws it (`#supportRoot`). `#titleSupporter` badge on the title.
- **What it unlocks (cosmetic only):** the `golden` theme in `THEMES` (`supporter:true`: Golden Hour, amber `#ffd54a`, teal `#ff8f6b`; hidden from the Stardust shop and ignored by `applyTheme()` without the pack) and **Gilded Machines**: `GILD` (`updateGild()`: owned and `PREFS.gild!==false`) makes `chassis()` blend each machine's colour 60% toward gold (`gildCol`) with gold rivets and outline; `machineSpr` keys and machine icon URLs carry `:g`.
- **Durable saves (v2.0.39):** Android's WebView writes localStorage to disk lazily, so swiping the app away soon after a save, or after importing a backup, lost everything since (testers saw all their saves vanish). In the store build `Storage.prototype.setItem/removeItem` are wrapped: every `ebi_*` write is mirrored to Capacitor Preferences (Android SharedPreferences) with a sequence number `ebi_seq` (`mirrorWrite`). `mirrorSync()` runs first in `initNative()`: mirror ahead of the WebView → restore every `ebi_*` key, `noSave`, reload once (`sessionStorage` `ebi_restored` guards loops); WebView ahead or no mirror yet → copy the WebView to the mirror. Reloads after a storage change go through `reloadSafe()` (waits for `mirrorFlush()`): backup import, dev reset. store-tests `saves_survive_lost_webview`, `mirror_catches_up`.
- **Startup can't break (v2.0.39):** `initNative()` runs last in the bootstrap inside a try/catch (it ran before the icons and save list were drawn, so any throw there left menus without icons and the title without saves), each part is guarded, and `appError()` shows the first error of a launch as a toast for testers to screenshot (also on `error` / `unhandledrejection`). store-test `startup_survives_plugin_error`.
- **Billing waits for the plugin's store (v2.0.40):** on a real phone `window.CdvPurchase` exists before `CdvPurchase.store`; `initBilling()` used to run as soon as `CdvPurchase` appeared, threw `reading 'register'` (a tester's screenshot), and had already set `billing.init`, so billing never started. It now returns false until `CP.store` exists, and `initNative()` retries on `deviceready` and every 500ms for 20s. store-test `billing_waits_for_store`.
- **Build:** see `docs/PLAY_STORE.md`. Fonts: `@fontsource/press-start-2p` latin + latin-ext woff2 in `www/fonts` with `OFL.txt`. Android versionCode = major×10000 + minor×100 + patch.

## Title screen & display prefs (v1.5.0)

- **PC title card (v2.0.37):** at 900px+ wide and 460px+ tall the `.title-card` becomes a two-column grid, `.tc-brand` (logo, tagline) on the left and `.tc-menu` (saves, buttons) on the right, with no max-height or inner scrolling; the narrow phone card scrolled inside itself on laptop screens once there were saves. Save rows keep their date on one line.
- **Living title screen** (`TITLE SCREEN` section, just above `CANVAS + RENDERER`): `#titleCanvas` sits behind a translucent `.title-card`. `buildTitleScene(zone,seed)` hand-lays one factory per zone from the game's own sprites (deposits, machines, belts with items, pipes). Scenes pan slowly and crossfade every `TITLE_SCENE_MS` (8s), and `#titleCaption` names the zone. It never touches `G`, so it runs before a save loads. `startTitleScene()` runs on load and in `quitToTitle()`; `stopTitleScene()` runs in `startGame()`. It is capped at 30fps.
- **`PREFS`** (`ebi_prefs`): `fps` caps `startRender()` (30 or 60; about 8fps behind a modal; nothing while the tab is hidden). `res` (`RES_STEPS` 100% to 10%) multiplies `CANVAS_DPR` in `sizeCanvas()`, and the canvas switches to `image-rendering:pixelated`. ☰ Settings has FPS, RES, 🔋 SAVER (30fps + 50%), ⏱ TIMER (see *Run timer*) and 🎨 COLOURS (colour-blind mode, see *Design System*). `setPref(k,v)` saves and applies, and `refreshSettings()` redraws the settings window if it is showing (`#settingsRoot`). Sim speed never depends on these. **Title screen SETTINGS (v2.0.32, `#titleSettings`):** `openSettings()` shows the same window everywhere (SFX `toggleSfx()`, Music `toggleMusic()`, volume `setMusicVol()`, now playing / NEXT, FPS, RES, SAVER, TIMER, COLOURS, HAPTICS, all in `PREFS`); with `onTitle()||!G` it only leaves out RESTART TUTORIAL and closes with CLOSE. `sfx()` reads `PREFS.sfx`; the title speaker (`toggleTitleMusic`) and in-game Music share `PREFS.music`. play-tests `sound_is_device_wide`, `title_settings` (runs last: it quits to the title).
- **Ground chunk cache:** floor and still deposits are baked once into `CHUNK`×`CHUNK` (16) tile canvases at 16px per tile (`groundChunk`). `draw()` blits those, then draws only `ANIM_RES` pool tiles per frame. The cache resets itself when `G.map`, the zone or the map size changes (load, zone change, `expandMap`); `invalidateChunks()` forces it. **Tile terrain must stay immutable after map generation**, or call `invalidateChunks()`.
- **`setHtml(el,html)`** rewrites an element only when its markup changed. The HUD and every auto-refreshed panel use it.

## Undo, haptics, install (v1.6.0)

- **Redo (v2.0.37):** `applyUndoGroup(ops,verb)` performs the opposite of each op newest first and returns the ops it performed, which is the step that reverses it: `undoLast()` pushes that onto `redoStack`, `redoLast()` (Ctrl+Y or Ctrl+Shift+Z, and a Redo card after Undo in the EDIT tab, UI icon `redo` = the undo arrow mirrored) pushes its result back onto `undoStack`. A rebuilt machine gets a new id, so `UNDO_REMAP` (old → new, read through `rid()`) lets older steps find it; remove snaps now carry `id`. A rebuild redone from a step that used the crafted pool takes one from the pool again (upgrades paid). Any new action (`pushUndo`) clears `redoStack`. Groups nest (`undoDepth`), so a splitter over belts inside a Shift+drag row stays one step. play-test `redo`.
- **Undo** (`UNDO` section, above `stampFits`): actions record ops with `undoRec()`; `undoBegin()`/`undoEnd()` group them (multi-select demolish/rotate, paste, blueprints). Ops: `place {id,src}` (undone by demolish; the refund goes back to `crafted`, inventory, or nowhere for dev free build), `remove {snap}` (rebuilds and pays the cost again; contents already went to inventory), `pos {list}` (move/rotate, put back by `relocate()`, all or nothing). Undo is the last card in the EDIT tab (the first until v2.0.19) (`DRAWER_DEFS.tools`, `action:'undoLast()'`: drawer items with an `action` run it instead of `setTool`), showing the steps left; `updateUndoBtn()` just refreshes that drawer. **New build actions must call `undoRec`**, and `tryRemove(x,y,true)` is the quiet form for batches.
- **Haptics:** `haptic(type)` runs at the top of `sfx()` (`HAPTICS` patterns), independent of the SFX toggle. `PREFS.haptics`, toggled in Settings; hidden where `navigator.vibrate` is missing (iPhone).
- **Install:** `beforeinstallprompt` is kept in `installEvt`; `installApp()` fires it, or shows Safari's Add to Home Screen steps on iOS. `canInstall()` hides everything once running standalone. Title button `#titleInstall` and a ☰ tile.
- **Belt corners:** `beltTurn(m)` returns 0 (straight: fed from behind, from both sides, or not at all) or 1/3 (fed only from one side). `beltCornerSpr(fr,turn)` maps each pixel to the straight tread by radius and angle so rails and studs line up; `beltItemPos(dir,turn,p)` moves items along the arc. Music keeps running into the game when the save's music is on (it crossfades to the zone's playlist), and the title playlist comes back after `quitToTitle()`.
- **Music engine (v2.0.17, `MUSIC ENGINE` section):** `MTRACKS` holds 19 track recipes: `ctx` ('title' or a zone number), `bpm`, `root` (MIDI), `scale` (`MSCALE`), `prog` (chord roots as scale degrees per bar, for the A / B / C parts), `form` (`MFORMS`: song, drive, ambient), instruments (`lead`, `arp`, `bass`: pulse25, pulse12, square, tri, saw, bell), `drums` (`MDRUMS`), `bassPat` (long, pulse, root8, octave, walk, synco), `rhy` (indices into the lead rhythms `MRHY`), `pad`, `swing`, `fx` (echo send) and `vol` (loudness trim, measured offline so every track plays at RMS about 0.02, the same as the original). Playlists: title 2, Ironfield 4, The Scar 3, The Deep 3, The Bloom 3, The Singularity 4. `compileSong(tr,n)` writes the notes: what plays in each part comes from `MROLES`. **Melodies are written, not random (v2.0.18):** `MMOT` holds 8 one-bar motifs (`[step,length,scale steps above the chord root]`, built from chord notes with passing notes on weak beats). A phrase plays its motif three times, following the chords in a steady register, then a cadence holds a note (`MCAD_OPEN` on the fifth mid-section, `MCAD_HOME` on the root at the section's end). A and the outro use motif `rhy[0]` (the hook, the same every play), B alternates between `rhy[2]` and `rhy[3]` from play to play, C holds long notes. Lead notes carry `lead:1`. Only accompaniment details (walking bass approach notes) are seeded per play. Before, every bar picked notes by a random walk through the scale, which sounded like random notes from the key. play-test `music_playlists` checks the hook stays the same and that bars 1 to 3 of a phrase share one rhythm. Bass never goes below 58 Hz (phone speakers). Factory Pulse, the original track (`_buildMusicSchedule`, `_MSCHED`), is kept note for note as a `raw` track on the title screen and in Ironfield. `mTick()` (every 100ms) schedules notes 0.5s ahead through `mPlay()` (Web Audio voices: periodic-wave pulses, noise drums, detuned saw pads, two-partial bells, vibrato on long lead notes) into a bus → compressor → `_music.gain` (`G.musicVol`), with a delay send. `musicCtx()` picks the playlist (title screen, else `G.zone`); when it changes, or NEXT (`musicNext()`) is pressed, the bus fades over 1.2s and `mNext()` picks another track from the playlist (never the same one twice in a row). There is a 2.5s pause between tracks. Settings shows `nowPlayingText()` (`#nowPlaying`) with NEXT. A new track: add an `MTRACKS` entry, then measure its loudness and set `vol`.
- Inventory panel now lists the `smelted` category (plates and bricks), which it never showed before.

## Core Rules

- Machines only receive inputs from inserters; belts can't feed machines directly. **Chests too since v2.0.43** (a friend's playtest: belts filled chests with no inserter, the one exception). A belt ending at a chest is a dead end (`beltDeadEnd`, `beltVisPass`), the item holds and the line queues, and a one-time toast says chests need an inserter (`chestBeltWarned`). Quantum Storage still takes belts (its Stardust description promises it); it now tallies what arrives per item in `m._sent`, which play-tests use as the counter at the end of a belt line (`sink()` in play-test.js).
- **Outputs go straight onto belts (v2.0.12):** `pushOutputsToBelts()` (in `gameTick`, just before `runBelts`) drops one item per tick from a machine's `outBuf` onto each belt, splitter or tunnel touching its output face (`outputTiles(m)`: every tile along the `PORTS` output side, rotated by `m.dir`), at a free gap (`beltDropPos`). A belt pointing back into the machine is skipped, and multi-output recipes alternate item types (`m._outN`). So a Miner or furnace needs no inserter to unload; inserters on an output face still work. Chests keep their items (they store in `chestInv`, not `outBuf`).
- **One item per arrow (v2.0.14):** a two-output recipe on a machine with two `PORTS` outputs puts output *i* (recipe order) out of arrow *i* (`portItems(m,i)`, `portTakes(m,i,k)`): the Cracker (now two arrows) sends raw fuel right and plastic bottom. Belts (`outputTiles` carries `port`) and inserters (`outputPortFacing`) only take that arrow's item; an item the current recipe doesn't make may leave by any arrow. Inserter turn groups are per arrow (`takerKey`: chest id, or `machineId:port`), so a plastic inserter never waits on the raw-fuel one. `drawPorts(...,m)` draws the item icon next to each such arrow, and the panel's MAKES rows say RIGHT / BOTTOM ARROW. Note the Cracker's bottom side is now an output face, so inserters can't feed it from below.
- Output → `outBuf` (stall at 50 total); `inBuf` cap 50 per item type (or `bufCap`). **Inserters only pick up what the machine takes (v2.0.44, `insTakes(dm,k)`):** an item whose buffer has room, and for a machine with recipes only the inputs of its recipe (any recipe it can run before one is set) plus paste for living machines; machines without recipes (generators, scrubbers, reactor, Singularity) take anything with room, `accepts` machines only theirs. Before, an arm grabbed the first item it saw and, with that buffer full (a furnace's coal), stood holding it so the ore never arrived and the furnace clogged; unusable items also filled buffers. play-test `furnace_inputs_dont_clog`. The machine panel shows each recipe input as its own buffer bar (INPUT BUFFERS, `n/cap`). A tester saw a Blast Furnace fed coal and ore 1:1 stop with coal at 50: it uses 2 ore per coal, and the arm then held a coal. On the live v2.0.42 that layout stalled at 50 plates; now it runs at full ore-limited speed (play-test `blast_furnace_own_buffers`). A mixed belt that dead-ends at the furnace still jams, because the spare coal has nowhere to go; it must carry on past or coal needs its own inserter.
- **Chests hold `CHEST_CAP` 200 items** (`chestTotal(m)`, `chestFull(m)`), filled by inserters only. Belts running straight into a chest ignored the cap until v2.0.42 (a tester saw stone pile up) and could fill chests at all until v2.0.43. The map bar, panel and `chest_full` award read the same constant. Chests already over 200 keep their items and take no more until they drop below. play-test `chest_needs_inserter_cap_200`.
- **Shared outputs (v1.9.8):** several inserters on one machine's output face, or on one chest, take turns. `buildTakers()` (every tick, before the inserter loop) maps each source to its inserters (`INS_TAKERS`); `myTurn()` lets the ready inserter (`insReady`) that was served longest ago grab, and `markServed()` records it (`_served`/`_serveN`, transient). A blocked inserter is skipped, so the others keep going. Before this the first inserter in update order took every item from a machine slower than an arm swing.
- **Splitters work with inserters (v2.0.11):** `beltLike(type)` (belt, tunnel, splitter) is what inserters treat as a carrier: they take from and drop onto all three. **Sides (v2.0.13):** each item entering a splitter gets a side (`it.side`, alternating via `splitSide`) and keeps it. A belt on that side takes it; with an inserter (or nothing) there, it moves onto that side's cell and waits (prog .99), and an inserter on a splitter takes only items with its own cell's side (`side===0` for the cell at `m.x,m.y`). If that side's cell is full, the item tries the other side's belt, else it is re-marked for the cell it is on, so a blocked side never jams the other. Two inserters on its outputs split evenly (play-tests `inserters_use_splitters`, `splitter_side_blocked`). **Overflow past an inserter side (v2.0.45):** an inserter side keeps one item parked for its arm (`it.park`, `parked(s)`), and anything more leaves by the other side (its belt, or its cell for an inserter there) while that has room; with both full the item waits and retries every tick. A parked item takes no room (`beltRoom` skips `park` items) and doesn't hold back the items behind it (`spaceBeltQueues`). Before, every item waited for its own side however long it took and the next one queued behind it on the cell: a tester's splitter with an inserter into a full chest on one side sent 0 a minute down the free belt (now 60, and a clean 30/30 when both sides take). play-test `splitter_overflows_blocked_side`. A drop onto a splitter used to land in its unused `inBuf` and vanish; `tidyBeltItems()` returns any such items to the inventory on load.
- Inserters only take from a machine's **output face** (`PORTS`). Every machine that produces items needs a `PORTS` entry, or inserters can't empty it and it can't drop onto belts (Zone 2 machines were missing theirs until v1.2.0, the Bloom's living machines until v2.0.17). play-test `living_machines_output` fails if any machine with recipes has none.
- Machines with `noItems:true` (pipes, pumps, tanks, Lumen Panels, Accumulators, Heat Sinks) refuse inserter deposits. A machine with `accepts:[...]` (Relief Valve: gaskets) takes only those, up to `bufCap`.
- **Pass 1** runs every machine with negative power (generators), then `runAccumulators()`. **Pass 2** runs everything else. Then belts, `settleFluidNets()` and `tickLiving()`.
- **Hard power cutoff:** `powerRatio()` is 0 or 1. Stone and blast furnaces are power-immune.
- **Throughput = Satisfactory, one to one (v2.0.8):** per minute, T1 / T2 / T3: **Miner and Oil Pump 60 / 120 / 240** (`MINE_TICKS` 4, `MINER_TIER_SPEED` 1/2/4; progress accumulates by the speed multiplier, so perks, modules, smog and radiant dust give exact rates; tiers are speed only, yield comes from perks and Productivity Modules), **belts, splitters and tunnels 60 / 120 / 270** (`BELT_T1_SPEED` .125 tiles/tick × `BELT_TIER_SPEED` 1/2/4.5, `BELT_CAP` 2 items per tile at least `BELT_GAP` .5 apart; `beltRoom(tile,p)` is the entry rule, so throughput is speed/gap with no whole-tick rounding), **inserters and long inserters 60 / 120 / 270** (1s cycle at T1, `INS_TIER_SPEED` 1/2/4.5). Coal Generators burn 15/min, as in Satisfactory. One T1 Miner → one T1 inserter → one T1 belt → one T1 inserter delivers 60/min (play-test `satisfactory_chain_keeps_up`). **Machines (v2.0.9):** every recipe `time` is whole seconds (a multiple of 4 ticks) and gives clean per-minute rates for every input and output (play-test `recipes_clean_rates` checks against 0.5, 0.75, 1, 1.5, 2, 2.5, 3, 3.75, 4, 5, 6, 7.5, 10, 12, 15, 20, 30, 45, 60, 90, 120, 180, 240). Stone Furnace 30 ore → 15 plates/min (one T1 Miner feeds two), Blast Furnace ×2, Electric Smelter ×4 (120 ore → 60 plates, one T1 belt). Furnaces, smelters, assemblers and labs take tiers as speed ×1 / ×2 / ×4 (`MACHINE_TIER_SPEED`), so a T2 machine is exactly two T1s (it was ×1.5 / ×2, and the panel wrongly said "speed & yield"). A machine checks for completion on its start tick too, so a one-tick cycle (1s recipe at T3) isn't stretched to two. Seven recipes lost one unit of one input to make the maths work: steel 4 plates (was 5), Evaporator 4 brine, Reactor Core 8 steel, Stellar Casing 2 bio composite, Void Engine 2 magnets, Quantum Mind 2 batteries. Oil smog is `OIL_SMOG` 0.25 per barrel, so smog per minute is unchanged at the doubled pump rate. **Advanced Logistics no longer speeds belts up; it unlocks belt upgrades** (`tierLocked()`), so belt numbers stay exact; the belt perks still add +20%/+40%. Inserters: an arm grabs without checking the belt and waits at the drop if there's no room (checking first lost most of a swing per item); a drop goes into any gap on the tile (`beltDropPos`); a pickup takes the front item anywhere on the tile (a T3 belt moves over half a tile per tick, so the old prog ≥ .9 window missed most items); finished deposits carry their leftover time and an arm that sat idle starts its swing at the current time. `runInserter` allows 10 phases per tick. `tidyBeltItems()` respaces every belt tile on load (at most `BELT_CAP`, a gap apart; extras to the inventory).
- **Tiers (v2.0.5, belts v2.0.6):** `TIER_TYPES` (Miner, Blast Furnace, Electric Smelter, Assembler, Lab, Inserter, Long Inserter, and `BELT_TYPES` Belt, Splitter, Tunnel) take T2/T3 upgrades; only `MODULE_TYPES` (the first five) get module slots. `tierCost(type,tier)` reads `TIER_COSTS`, or the cheaper `INS_TIER_COSTS` for inserters (T2: 2 gears + 1 circuit, T3: 1 steel + 2 circuits); `tierBonus()` is the label. Inserters swing faster with tier (`INS_TIER_SPEED` 1 / 2.5 / 4, applied in `insMs(ms,m)`, so the arm animation, the sim and `machineRates` agree) and show the tier badge. The carry-over cap `insMs(TICK_MS)` stays unscaled. **Belts, splitters and tunnels** move items `BELT_TIER_SPEED` 1 / 1.5 / 2× faster per tile (`beltTierMult(m)` × `beltBaseSpeed()` in `runBelts`, the tread animation and `drawBeltItems`), cost `BELT_TIER_COSTS` per tile (T2: 1 gear, T3: 1 steel), and show their tier by stud and rail colour (`BELT_TIER_COL`: amber, red, blue; `beltSpr(fr,tier)`, `beltCornerSpr(fr,turn,tier)`); splitters and tunnels also get the tier badge. Items cross tier boundaries with the usual `carryProg`, so a slower tile is a bottleneck.
- **Build tier picker (v2.0.46, user request):** once upgrades are open (`tiersOpen()`: Advanced Logistics researched, or any machine already above T1) the BUILD drawer shows three squares T1 / T2 / T3 in its bottom right (`#drawerTiers`, `.dtier`; a column in portrait, a row along the bottom of the side drawer; hidden in EDIT). The pick (`buildTier`, `setBuildTier(t)`, not saved) applies whatever group is open: every `TIER_TYPES` machine is placed at that tier (`placeTier(type)`; belts only while `tierLocked` allows; other machines stay T1). `placePay(type,used)` says what one costs: `machineWorth(type,tier)` from the inventory, only the steps (`tierSteps`) when one is waiting in `G.crafted`, nothing in dev free build; `payPlace()` takes it. Cards (`buildChips()`, a T2/T3 badge `.dtb`), the `#buildCost` bar (name + T2/T3), the resource strip outlines, line plans and their total (`linePlan` pays from a copy of the inventory, crafted first) and the ghost (tier badge) all follow it. Used by `tryPlace`, `completePlacement` (so Shift+drag rows too) and `placeLine`. Undo: `placeOp()` records the tier only for a free placement; a crafted one records none (and `stampMachine` records tier 1 for `src` crafted), so undo hands the machine back to the pool and refunds the paid steps. play-test `build_tier_picker`.
- **Upgrade tool (v2.0.5, EDIT tab):** tap one corner, then the opposite corner (`upgState`); `#upgradeBar` lists how many will go up a tier, the total cost (`upgPlan()`), and a chip per machine type to switch types off. ⬆ UPGRADE (`upgradeSelected()`) raises each one tier, paying per machine and skipping what can't be afforded; the selection stays, so a second press goes to T3. Selected machines get a green outline and arrow (maxed ones dim). Leaving the tool clears it (`upgClear()`). Upgrades are not undoable (same as the panel's UPGRADE).
- **A machine's value is `machineWorth(type,tier,modules)`:** build cost + each tier step (`tierCost`) up to its tier + installed modules. Demolish refunds it, paste/blueprints charge it (copies keep their tier; modules are not copied), and undo rebuilds charge it. Use it for anything that creates or destroys an upgraded machine.
- Speed multiplier = power × perks × tier × modules × smog efficiency × life stage. Pumps (oil, brine, enzymes) also scale with tier.
- **Belts:** item `prog` is not clamped at 1; an item is done at `BELT_DONE` (1−1e-6, since 10×0.1 < 1) and the next tile gets `carryProg()` (the leftover move). Before v1.9.2 each tile took an extra tick and items froze at the edge. Splitters route from **both** cells (the second cell used to delete its items). Items are drawn in their own pass after all belts (`drawBeltItems`, no clipping; see *Belt drawing*); splitter cells and tunnel mouths draw their items too. play-test `belt_item_smooth` renders 650 frames and fails on any jump, stall or missing frame.
- **Belt drawing (v2.0.17):** after the belts and inserters move each tick, `beltVisPass()` (end of `runBelts`) gives every belt item a display position in `BELT_VIS` (a WeakMap, never saved): its real progress, held a `BELT_GAP` behind the item ahead (across tile edges, into the next belt-like tile; end of a line: `1-BELT_GAP/2`), never moving backwards and at most 1.5× belt speed (catching up after a pickup). `drawBeltItems()` then draws each item through `beltItemWorld()`, sliding from last tick's display spot to this tick's: along the path when it crossed from the tile feeding it (`beltFeeds`, corners included), straight for a hop between neighbouring cells (splitter sides), in place after a teleport (tunnel). Drawing runs one tick behind the simulation. Before, the renderer guessed whether a tile was flowing (`beltCanTake`: fewer than 2 items on the next tile); on a busy belt every tile holds 2, so tiles flipped between drawing modes every tick and items jumped up to half a tile. play-test `belt_busy_smooth` checks free flow, a queue, a T2 belt drained by a T1 inserter, a tunnel and a side-loading inserter.
- **Queues keep their gaps (v2.0.18):** after the transfer passes, `spaceBeltQueues()` (in `runBelts`, before the inserters) holds every item a `BELT_GAP` behind the one ahead, across tile edges too (tiles visited downstream first, memoised; splitters and tunnel entrances don't cap their front item). At a dead end (`beltDeadEnd`: a machine, nothing, or an unlinked tunnel ahead; not a chest or another belt) items stop at `END_HOLD` 0.75 while advancing, a half gap short of the edge. Before, a stopped line parked every item at the edge (prog .99, two per tile on the same spot); the drawing spaced them out on its own, and when the line started again they poured out two at a time and the picture lurched forward at up to twice belt speed to catch up. Moving items were already a gap apart, so throughput is unchanged (all throughput play-tests pass). play-test `belt_queue_restart` checks a full T1 and T3 line, and an extended one, setting off at exactly belt speed.
- **Belt transfer (v2.0.7):** `runBelts` moves arrived items with `moveTile(tx,ty,final)`. **Remove arrived items with `prog<BELT_DONE`, never `prog<1`**: the old `prog<1` filter kept an item at 0.9999999 on its tile and also moved it on, so one item object sat on two tiles; a back-pressure reset on one froze the other. T2/T3 speed sums (.225, .3) hit that window constantly, so v2.0.6 T3 lines deadlocked and T2 lines duplicated items. A blocked item keeps its `prog` and retries in up to 4 alternating-direction passes (`waiting`), so a full belt carries the same flowing right/down as left/up (T1 137.6, T3 240 items/min; it was 124.8/221.6 right or down); only items still blocked after the retries get `prog .99` (`hold()`). Tunnel mouths accept at most 4 items from a belt (before, one held 1,700). `tidyBeltItems()` in `migrateSave()` returns anything past 4 per belt tile, or on a tile with no belt, to the inventory (toast via `G._tidied`).
- Recipe progress bars use `m._dur` (the real cycle length), not `rec.time`.
- The map render loop is frame-capped by `PREFS.fps`; never assume `draw()` runs every rAF.
- Canvas animation uses the smooth clock `at = now/TICK_MS` inside `draw()`, never `G.tick` (which only steps 4×/s and speeds up at dev speed). Belt interpolation divides by `tickInterval()`; inserter timings use `insMs()`.

## Systems by zone

### Zone 2: Smog
**v2.0.15 rebalance (smog had done nothing below two pumps):** smog per minute at T1 while working, `SMOG_PER`: Oil Pump +20 (per barrel), Cracker +15 and Refinery +15 (per craft, so tiers scale it), Combustion Gen. +20 (per fuel burned); `addSmog()` applies Clean Burn ×0.7. It clears `SMOG_DECAY_MIN` 6/min by itself; each powered, fuelled Scrubber clears `SCRUBBER_SMOG_MIN` 60/min and burns 1 refined fuel per `SCRUBBER_FUEL_TICKS` 16 (15/min). So one pump + Cracker + Refinery (+50/min) needs a Scrubber. `smogBudget()` sums what is making and clearing smog now; the GOAL panel shows it and says when to add a Scrubber. Machine panels show `machineSmog(m)` for emitters. **Panel rates are full-speed numbers** (smog changes every tick and made them flicker); a separate note says how much smog is slowing the machine. Speed × `max(0.1,(100−smog)/100)`. Scar Notes are made from gears + coal (lab or hand), so Oil Extraction can be researched before any oil exists.

### Zone 3: Fluids & pressure (reused in Zones 4–5)
- **Cave walls (v2.0.28, `T_WALL` tiles, Zone 3 only):** `carveCaves(map,salt)` runs after `buildZoneMap(DEPOSITS_Z3)`: a cellular automaton (`CAVE_FILL` 45%, five smoothing passes, the floor below counts as open) grows rock in the ore fields, then every deposit keeps a 1-tile clear rim, the landing cavern round the arrival camera (`CAVE_START` 29,26, radius 7) stays open, lone rock specks go, pockets under 14 tiles with no deposit fill in, and every other cavern is joined to the landing cavern or the Factory Floor by a 2-wide passage carved along the shortest way through the rock. About 30% of the ore fields end up rock. Walls only replace open ground; the Factory Floor never gets any. `terrainOk()` refuses every machine on rock (including pipes and the Quantum Extractor); belt tunnels link across it (their 5-tile reach is unchanged), pipes go round. Tapping rock, or failing to place on it (`onWall()`), shows `wallHint()`. Saves pack a wall as `#`. Old Zone 3 maps keep no walls (only new maps get them). The Zone 3 title scene has some rock too (`S.wall`, `rock()`). play-test `cave_walls` checks six generated maps (connected, 15 to 45% rock), the floor, placement, a tunnel under rock and the save round trip.
- `fluidCap` machines (Pipe 10, Fluid Tank 200, Relief Valve 5) flood-fill into networks every tick (`buildFluidNets`). `fluidPort` machines attach to adjacent networks (`m._nets`).
- One fluid per network. `fluidsWouldMix()` refuses a placement that would join two fluids.
- Pressure = amt / cap. Pumps (`pumps:'brine'|'enzymes'`, placed on their pool) add 1 unit every 2 ticks, even when full.
- Recipes with `fluid:{...}` draw at start. They need ≥ `LOW_PRESSURE` (20%) and ≥ `minPressure` (Rod Press: 60%).
- ≥ `OVER_PRESSURE` (90%) with inflow: strain +2 per push. It holds between pushes and falls 2/tick below 90%. At `burstStrain()` (80, or 120 with Reinforced Pipes) `burstPipe()` destroys a random pipe and halves the fluid.
- **Relief Valve setting (v2.0.29):** each valve opens at its own pressure, `m.relief` in `RELIEF_STEPS` 60/70/80/85 (`reliefAt(m)`, default `RELIEF_AT` 80), chosen with the OPENS AT buttons in its panel (`setRelief(id,v)`). No 90%: strain starts at `OVER_PRESSURE` 90, so a valve holding a network at 90% would let it burst. `settleFluidNets()` runs a network's valves lowest setting first, each venting what is above its own setting. Paste, blueprints (`cleanBlueprint` keeps a valid `relief`), undo rebuilds and `stampMachine` keep the setting. The Pressure panel lists each network's valve settings. A lower setting keeps the network far from bursting but vents fluid machines could have used. play-test `valve_threshold`.
- **Relief Valves (v2.0.17):** each vents at most `VALVE_VENT` 0.25/tick (60/min, half of a T1 pump's 120/min) above its setting (80% unless changed), splitting the excess between valves, so a network needs about one valve per half pump of surplus. Venting wears the fitted Gasket (`m.seal`, `VALVE_SEAL` 60 units); a worn one is replaced from `inBuf.gasket` (buffer `bufCap` 10, fed by inserters or LOAD GASKETS in the panel, `loadGaskets()`); with none left the valve jams shut (`valveJammed(m)`, red blinking frame on the map, a toast once per jam, `_jamWarned`). A new valve comes with one gasket fitted (`seal` undefined counts as full). Gasket: `mk_gasket` (Assembler, 1 iron plate + 1 stone → 2, 2s) or the same by hand, both `pressure_control`. Machines can now declare `accepts:[items]` (inserters only grab those for it) and `bufCap`. Old saves: every valve gets 4 spare gaskets and a toast (`G._gaskets`). Before v2.0.17 one valve vented 0.75/tick for free, more than any pump, so one valve anywhere made a network burst-proof.
- **Glow tide:** `GLOW_CYCLE` 960 ticks, bright for the first 720. Lumen Panels give 40 kW only while bright.
- **Accumulators** hold `ACC_CAP` 2,000 kJ: they charge from surplus and cover a shortfall only when they can cover all of it.

### Zone 4: Living machines & reactor

Saves older than 2.0.20 with heat sinks get a toast. `migrateSave()` now sets `G.ver` to the build that loaded the save (it used to stay at the build that started the game), so notices can be gated by version.

## Coding Conventions

- **No em dashes or en dashes anywhere in the game** (the user asked). Use a colon, a full stop, a comma or a middle dot (·).
- **Always ask before changing existing logic** (from the GDD). Bugs found along the way get reported. Fix them when they block the requested work, and say so.
- Single `index.html`, vanilla JS, no libraries; all state in `G` via `defaultState()`.
- New zone content: add items, recipes (append ids to the machine's `recipes`), `MDEFS` (with `PORTS` if it outputs items), `TECHS` (`zone:n`), the `ZONES` entry, deposits, `ZONE_TUTORIALS`, `ZONE_MILESTONES`, achievements and drawer category.

- **Rotate / flip while pasting (v1.9.3):** the paste bar (`#ghostBar`) has ↻ ⇆ ⇅ buttons → `transformGhost('rot'|'h'|'v')`, which replaces `multiselState.clipboard` or `blueprintState.data` with `rotateLayout()`/`flipLayout()` output (new entry objects, so saved blueprints never change). Positions use each machine's footprint (`machSize(type,dir)`) and directions turn with the layout (flip h: right↔left, flip v: down↔up, rotate: +1). Ghosts draw facing arrows or output ports (`drawGhostEntry`).
- **Placement rules live in one place:** `terrainOk(type,tile)` (used by `canPlace`, multi-select move and paste), `refreshMineRes(m)` after any move, `linkTunnel(m)`/`unlinkTunnel(m)` (two-way search), and `stampMachine()`/`stampFits()` for blueprints and paste. Don't hand-roll machine creation.

**Every delivery checklist:**
1. Bump `sw.js` cache version, `VER`, the title-screen `v-num` and `package.json` `version` (the Android versionCode comes from it)
2. Run `node tools/check.js`, `node tools/play-test.js`, `node tools/touch-test.js` and `node tools/store-test.js`: everything passes, no page errors
3. Verify the file starts with `<!DOCTYPE html>`

### Known Gotchas
- Closing the EDIT tab, or leaving it for another tab, calls `setTool('select')` when an `EDIT_TOOLS` tool is active (a held machine goes back).
- **Machine panel (v2.0.10):** each MAKES / USES row has an arm hint (`armHint`: the inserter tier that carries that rate alone), the recipe picker lists every recipe per minute at the machine's tier (`recipeRates(m,rid)`, which runs `machineRates` with the recipe swapped in), the upgrade box says what the next tier makes, and the build-info popup lists recipes per minute at T1 plus the tier steps. **Machine panel rates:** `machineRates(m)` returns `{out,in,notes}` per minute from the same numbers the simulation uses (miner/pump cycles, recipe `_dur` maths, fuel ticks: `BURNER_COAL_TICKS`, generator 16, combustion gen/scrubber 32, `ROD_TICKS`, living `FEED_EVERY`). A machine with no power shows full-speed rates. `ratesHtml()` renders PER MINUTE (MAKES / USES); **change a machine's timing and update `machineRates` too** (play-test `rates_match_sim` checks Miner, Stone Furnace and Burner). The old measured rate row is now "Actual output".
- **Machine panel action bar (v2.0.30):** every machine panel starts with the same four buttons, `machActionsHtml(m)`: ROTATE (with the facing arrow) · MOVE · PAUSE/RESUME · DEMOLISH, always in that order (`.mach-actions`, `.ma-btn`). ROTATE is live where facing matters (`machFaces()`: `DIR_TYPES`, anything with `PORTS`, non-square machines) and dimmed elsewhere; PAUSE is dimmed for `NO_PAUSE` (belts, splitters, tunnels, chests, Quantum Storage, pipes, tanks, heat sinks: nothing to pause). A dimmed button explains itself (`machNoop`). Before, ROTATE showed only on belts, inserters, tunnels and splitters (assemblers and other machines with output arrows could only turn with the EDIT tool), MOVE and DEMOLISH sat mid-panel after the recipes and PAUSE at the very bottom. Inserters now honour PAUSE (they ignored it before, though the panel offered it). DEMOLISH is the only remove button. play-test `machine_actions_and_building`.
- The manual mining popup (`#resInfo`) closes whenever a menu opens: `switchTab()`, `togglePanel()` and `showModal()` all call `closeResInfo()`.
- **Page-clock timestamps don't survive a reload.** Inserter arms time swings with `performance.now()`, which restarts near zero on every page load. `migrateSave()` calls `resetArmClocks()` (an arm holding an item finishes its drop, an empty arm goes idle), and `stepInserter()`/`draw()` pull any future `stateStart` back to now. Before v1.9.5 every reload left inserters spinning and stuck. Never store `performance.now()` values in `G` without resetting them on load (wall-clock `Date.now()` is fine). The pipe-burst flash (`burstFx`) also pulls a future start time back to now.
- **Audio needs a user activation, and pointerdown from a touch is not one.** An `AudioContext` created then stays `suspended` (silent music and SFX). `unlockAudio()` resumes it on `pointerup`/`touchend`/`click`/`keydown` (capture) and starts the title music there; `visibilitychange` tries to resume too, since phones suspend audio when the app is switched away. Broken from v1.7.0 to v1.9.5. **Title screen (v1.9.7):** `tryTitleAutoplay()` starts the music on load where allowed (Chrome: apps installed to the home screen); otherwise `#titleSoundHint` (TAP FOR SOUND) shows until audio runs. A first tap on `#titleMute` starts the music instead of muting it (`unlockAudio` skips that button; `toggleTitleMusic` starts when music is on but not playing).
- Touch taps never fire mousemove, so `handleTap()` sets `hov` itself (the build ghost follows taps). Picking a machine puts its ghost mid-screen. A long press inspects; it used to demolish.
- UI refresh (HUD, open panel, drawer) is skipped while a pointer is down (`uiPress`), and the drawer only rebuilds when its markup changes. Rebuilding mid-tap swapped the button under the finger and lost the tap.
- `transitionToZone()` keeps the dev settings (speed, free build, free craft) and restarts the clock.
- Touch events fire synthetic mouse events (`lastTouch` debounce in `setupInput`). `setupInput()` attaches listeners once (`inputReady`); before v1.4.0 every new game or load doubled them
- `perkMult()` returns multipliers; `power` multiplies draw
- `recordOutput()` uses `Date.now()`, so rates look huge in fast headless tests
- `machSize()` is the canonical size helper: **every non-square machine (Splitter, Scrubber) lies on its side facing down/up** (v1.9.4). Never read `MDEFS[t].size` for a placed machine. `drawMachSpr()` draws a sideways machine turned a quarter (map and ghosts), and `rotateM()` frees and re-claims tiles whenever the footprint changes (refused if there is no room)
- `completePlacement()` duplicates `tryPlace()` minus the power check, so keep them in sync
- `buildToolbar()` just calls `buildDrawer()`; `buildTitleSlots()` after `quitToTitle()` and on load
- Fluid networks rebuild every tick. Never store a network reference across ticks except via `m._net`/`m._nets` (transient)
- `PRESTIGE` is a cached global. Call `savePrestige()` after changing it
